# ver2_save_and_load

スケジュール管理アプリ（ミニ）のVer.2。Ver.1（予定の追加・一覧表示）に、ファイルへの保存・読み込みを追加した。

## Ver.1からの変更点

- プログラム終了時（メニュー`0`）に、登録されている予定をすべて `schedules.txt` に自動保存する。
- プログラム起動時に、`schedules.txt` があれば自動的に読み込む。ファイルが無い場合（初回起動時）は、何もせず空の状態で始まる。
- 保存形式は1件につき1行、`年,月,日,予定` のカンマ区切り。
- 予定の内容を空のまま追加しようとした場合はエラーとし、追加を中止する（理由は下記「設計上の注意点」を参照）。

## プログラムについて

Ver.1と同じく、対応している操作は次の3つ。

- `1`：予定を追加する
- `2`：登録済みの予定を一覧表示する
- `0`：終了する（このタイミングで自動保存される）

## 使い方

```bash
gcc -Wall -Wextra -o schedule schedule.c
./schedule
```

1回目の起動で予定を追加して `0` で終了すると、同じフォルダに `schedules.txt` が作成される。

```
$ cat schedules.txt
2026,8,1,夏休み計画
2026,8,15,お盆休み
```

2回目以降の起動では、このファイルの内容が自動的に読み込まれ、`2` で一覧表示するとVer.1同様に確認できる。

## 入力に関する注意事項

- 年月日の入力形式（半角スペース区切り・8桁連続表記のみ対応、ハイフン区切り等はエラー）はVer.1と同じ。
- 予定の内容を空にして追加しようとすると、「予定の内容が入力されていません。追加を中止します。」と表示され、追加されない。

## 設計上の注意点（空タイトルを弾く理由）

保存形式は「年,月,日,予定」のカンマ区切りで、予定の部分は読み込み時に `%[^\n]`（改行の手前までを1文字以上読み取る指定）で解析している。もし予定が空文字のまま保存されると、ファイル上は `2026,9,1,` のように予定の位置に何も無い行になり、`%[^\n]` は0文字にはマッチできないため、読み込み時にこの1件だけが解析に失敗し、静かに消えてしまう。

保存・読み込みの仕組みを複雑にするよりも、そもそも空の予定を登録できないようにする方がシンプルなため、入力時点でチェックするようにしている。

## ファイルが壊れている場合の挙動

`schedules.txt` を手動で編集するなどして、以下のような行が混入した場合は、その行を読み込まずにスキップし、スキップした件数を起動時に表示する。

- カンマの数が合わない行（例: 予定の内容が完全に欠けている行）
- 数値であるべき箇所が数値になっていない行
- 月が1〜12の範囲外、日が1〜31の範囲外になっている行
